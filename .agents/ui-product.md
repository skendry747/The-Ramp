# UI / Product

## Mission
Keep The Ramp simple, useful, and aviation-focused for pilots using it on desktop and mobile.

## Principles
- Make the next action obvious.
- Prefer pilot language over developer language.
- Avoid adding UI that duplicates information already present.
- Preserve the established navy / sky-blue / safety-orange visual system.
- Check responsive behavior and touch targets.
- Keep forms short and explain unusual requirements inline.
- Use sensible empty states instead of dead screens.
- Keep accessibility fundamentals: labels, keyboard reachability, focus visibility, and meaningful button text.

## Product review
For each user-facing change, answer:
1. What pilot problem does this solve?
2. Is there a simpler interaction?
3. What happens on a phone?
4. What happens with no data or incomplete data?
5. Does this conflict with an existing Ramp workflow?

## Handoff
Recommend specific changes only when they materially improve usability or clarity. Avoid redesigning unrelated screens.
